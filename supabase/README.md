# ذخیرهٔ ابری و حساب شخصی

فایل `migrations/202611220001_personal_invest.sql` را یک‌بار در SQL Editor پروژهٔ موردنظر Supabase اجرا کنید. این تغییر جدول‌های گزارش، سابقهٔ اجرا، سبد، معاملات، موقعیت‌ها، دیده‌بان، هشدارها و تنظیمات را می‌سازد. دادهٔ روزانه و دفتر معاملات در دو تراکنش مستقل ثبت می‌شوند. تاریخچهٔ حجیم قیمت می‌تواند محلی باقی بماند.

در بخش Authentication یک کاربر شخصی با ایمیل تأییدشده بسازید. برای حساب شخصی می‌توانید ثبت‌نام عمومی را در تنظیمات Auth غیرفعال کنید. برای اینکه این کاربر گزارش‌های موتور را ببیند، UUID واقعی او از Authentication → Users را جایگزین کنید و در SQL Editor اجرا کنید.

```sql
insert into investment_private.report_readers(owner_id)
values ('YOUR-AUTH-USER-UUID') on conflict do nothing;
```

موتور پایتون و GitHub Actions از متغیرهای محیطی `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` استفاده می‌کنند. کلید دوم فقط برای محیط قابل اعتماد موتور است. اپ با نشانی پروژه، کلید عمومی و نشست کاربر از Supabase Auth به داده دسترسی دارد. هر کاربر فقط سبد، معاملات، دیده‌بان، هشدارها و تنظیمات خودش را می‌بیند. دسترسی به متن گزارش روزانه به کاربران مجاز در جدول بالا محدود شده است.

هر معاملهٔ دستی باید یک بار با UUID ثابت در دفتر ثبت شود. برای تلاش مجدد همان شناسه را بفرستید و در صورت تداخل، رکورد قبلی را بررسی کنید. ثبت معامله و به‌روزرسانی موقعیت اتمی است. قیمت‌ها، کارمزد و بهای تمام‌شده همه به ریال هستند. بهای تمام‌شدهٔ فروش با میانگین موزون محاسبه می‌شود. ثبت فروش بالاتر از موجودی و ثبت معامله پیش از آخرین معاملهٔ همان نماد در همان سبد رد می‌شود. مقادیر سفارش، کارمزد و قیمت در پایگاه داده نیز بررسی می‌شوند.

برای تست دو حساب و سیاست‌های RLS، پس از migration فایل `tests/portfolio_rls.sql` را روی یک دیتابیس آزمایشی Supabase با نقش مدیر اجرا کنید. تست خرید، فروش، کارمزد، منع فروش اضافه، محرمانگی داده و منع انتشار گزارش توسط اپ را می‌سنجد و همهٔ تغییراتش را rollback می‌کند.

اجرای تست‌های آفلاین همگام‌سازی از ریشهٔ پروژه

```powershell
python -m unittest discover -s supabase/tests -p "test_*.py"
```
